This is the original preamble of the course prompt pack, unchanged. Save the MASTER RULES section as AGENTS.md (and CLAUDE.md pointing to it, if you use Claude Code) in your empty project before running F01.

The prompts mention a GPT-6 coding assistant; any capable coding assistant works (Claude Code, Codex, GitHub Copilot). See README.md in this folder for the build order, including the follow-up prompts.

## How to run


1.	Open an empty project folder in VS Code. Paste MASTER RULES into a persistent repo instructions file (for example AGENTS.md) and ask your coding assistant to follow it.

2.	Execute F01, then F02, F03 and F04 sequentially. Commit and test after each.

3.	For each lab, start an OpenSpec change. Review proposal.md, specifications, design and tasks before permitting implementation. Apply, test, verify against specifications, archive, and commit.

4.	Use the copy-ready prompt beneath each heading as a single GPT-6 request. Never paste all 75 at once.

5.	The assistant's OpenSpec command spelling depends on integration: OpenSpec docs show /opsx:propose and /opsx:apply for some agents, while Codex uses $openspec-propose and $openspec-apply-change. If these are not installed, use the equivalent commands generated by openspec init.

## MASTER RULES — save as AGENTS.md

You are implementing a production-quality educational platform named mastra-learning-platform and a 75-lab Mastra TypeScript course.

Never invent Mastra methods, exports, package names or model identifiers. First inspect installed versions and the official version-matched docs; use documented provider/model strings and do not assume ChatGPT subscriptions provide API access. Pin exact tested versions in the lockfile and note compatibility in docs.

Keep Mastra and credentials on the server. Frontend calls our typed API and receives SSE events. Use accessible React/TypeScript UI; Express/Zod server validation; strict TypeScript, Vitest, Playwright and CI.

One OpenSpec change per foundation prompt/lab: draft proposal/spec/design/tasks, show decisions, implement only approved scope, test, verify, archive. The user can explicitly request automated approval, otherwise expose plan for review.

Preserve the existing foundation, module order and lab registry. Do not rewrite working labs, modify contracts without migration, expose private keys or claim features absent from the actual Mastra version. Use adapters when capabilities are ecosystem integrations rather than native framework APIs. Lab routes must remain stable: /labs/lab-XX and ?lesson=lab-XX compatibility.

Every lab must be pedagogically complete: concept, objectives, prerequisite checks, at least one meaningful input, Learn/Run/Source tabs, expected output, incremental execution/log/tool/workflow events where applicable, guided instructions, hints 1–3, common mistakes, challenge, short quiz (3–5 questions), safe readable reference source, automated objective checks, test fixtures, instructor video outline (3–7 minutes) and learner progress persisted. Follow the established LabDefinition contract.

Provide a deterministic offline/mock mode for normal unit tests, and optional live provider mode with user-configured API keys and cost notices. Ensure server-side timeouts, cancellation, input limits, secrets masking and error handling. Never execute student-submitted arbitrary code inside the API process; future remote execution requires an isolated sandbox with network and resource restrictions.

On finishing each change, report file paths, commands run, test results, demo steps, any model/provider costs, unsupported features and open issues. Do not mark work complete unless tests actually passed.


## Common lab delivery contract


Each Lxx prompt below inherits all MASTER RULES. Implement it in the existing mono-repo, not as a fresh standalone project. Register its unique ID and title in the shared catalog; use proper module grouping. Integrate all Learn/Run/Source tabs, control panels and SSE events. Make the lab fully testable offline and optionally live. Keep individual reference implementation under packages/labs/src/lab-XX/ (adapt path to actual project convention). Implement beginner-friendly docs, input/output JSON examples, validation and instructor outline. Do not silently omit requested capabilities; if they are not native to the installed version, create an explicitly documented app-level implementation or feature detection.
