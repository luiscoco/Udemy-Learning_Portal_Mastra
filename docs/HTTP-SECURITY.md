# HTTP security boundary

Local development remains HTTP on loopback. API-served responses, including parser/auth errors and the built web app, receive CSP, nosniff, no-referrer, deny-framing, same-origin opener and restricted device permissions. The CSP permits same-origin scripts without inline scripts or eval, inline styles needed by layout/diagrams, and local data/blob image/audio/worker resources. The early saved-theme script is an external same-origin asset. Microphone access remains self for the voice lesson; camera and geolocation are disabled.

`HTTP_REQUIRE_HTTPS=false` is the local default. Set it to true only behind an explicitly trusted TLS proxy. Insecure application requests then return a canonical 403 without redirecting a credential-bearing body. Non-credentialed GET `/api/health` and `/api/ready` probes remain available to container health checks. HTTPS responses carry HSTS `max-age=31536000`, without preload or a subdomain commitment. Untrusted X-Forwarded-Proto cannot turn HTTP into HTTPS; `TRUST_PROXY=true` is refused when HTTPS enforcement is enabled. Configure the actual hop count or trusted loopback topology.

`CORS_ORIGIN` is optional and must be one canonical HTTP(S) origin, such as `https://learn.example.com`, without a trailing slash, path, wildcard, credentials or query. The API sets credentialed CORS headers only for that exact configured origin; same-origin clients work without it. API preflights allow GET/POST/OPTIONS and the typed client's known request headers. Unknown origins, methods and headers are refused. Responses vary by Origin. The existing session, owner and mutation capability checks still apply; CLI clients without Origin remain compatible. SameSite=Strict is unchanged, so this is not a promise of authenticated cross-site cookie access.

The local student setup needs no CORS_ORIGIN, proxy trust or HTTPS-required option. Do not expose its development identity provider to a public interface. Compose remains loopback-bound HTTP; optional Azure staging uses its managed TLS ingress, one trusted hop and the HTTPS option. No cloud changes were performed by implementing these controls.

The implementation follows [Express security guidance](https://expressjs.com/en/advanced/best-practice-security/) and the [CSP reference](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy). Full browser verification checks the production build, saved theme and representative diagram/source/voice workspaces under the actual policy.

Browser startup configures Zod 4.6.7 with `jitless: true` before catalog/API schemas parse, avoiding its caught eval probe under CSP. This uses the [documented Zod setting](https://zod.dev/compile#content-security-policy), not a relaxed script policy. The SPA index is served from an explicit constant path even beneath a hidden installation parent; other dotfiles remain unavailable.
