# course-labs/lab-22-threads-and-user-boundaries Specification

## Purpose
Lab 22 teaches explicit resource and thread identifiers and an owner-checked thread boundary over Mastra memory: create, list, history, send, reset and delete, with a uniform not-found answer.

## Requirements

### Requirement: Explicit resource and thread identifiers
Every thread operation in Lab 22 SHALL carry the signed-in user (resource) and a server-generated thread id.

#### Scenario: Create
- **WHEN** alice creates a thread titled "Porto trip"
- **THEN** it is owned by alice's resource id and its id is a UUID generated by Mastra

#### Scenario: List
- **WHEN** bob lists threads after alice and bob each created one
- **THEN** bob's list contains only bob's thread

### Requirement: Separate users cannot retrieve each other's threads
With the `guarded` strategy, any history, send, reset or delete on a thread the caller does not own SHALL be refused with `NOT_FOUND` and SHALL NOT read or change the thread.

#### Scenario: Bob attacks alice's thread
- **WHEN** bob tries to read, send to, reset and delete alice's thread
- **THEN** each attempt returns `NOT_FOUND` with message "Thread not found", no data is returned, and alice's thread still has its messages

#### Scenario: No enumeration
- **WHEN** bob reads alice's thread and, separately, a thread id that does not exist
- **THEN** both responses are identical and contain no other user's id

### Requirement: Safe reset
`reset` SHALL remove the thread's messages while keeping its id, title and owner; only the owner may reset.

#### Scenario: Owner reset
- **WHEN** alice resets her thread
- **THEN** its history is empty, and it is still listed for alice with the same id and title

### Requirement: Raw Mastra contrast
With the `raw-mastra` strategy, the lab SHALL show what the raw memory API allows, and the boundary checks SHALL fail.

#### Scenario: Raw delete across users
- **WHEN** bob deletes alice's thread with the `raw-mastra` strategy
- **THEN** alice's thread is gone and the `no-cross-user-write` check fails
